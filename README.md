# jlox

A tree-walking interpreter for the **Lox** language, written in Java. Source
goes in, values come out — no bytecode, no VM. Built while working through
[_Crafting Interpreters_](https://craftinginterpreters.com/) by Robert Nystrom.

```lox
fun makeAdder(x) {
  fun add(y) { return x + y; }
  return add;
}

var add5 = makeAdder(5);
print add5(3);   // 8
```

---

## How it works

`Lox.run()` pushes the source through four passes. Each one finishes completely
before the next starts, and an error in any pass halts the chain.

```
source ──▶ Scanner ──▶ tokens ──▶ Parser ──▶ syntax tree ──▶ Resolver ──▶ Interpreter ──▶ value
```

| Pass            | In → Out                        | Job                                                              |
| --------------- | ------------------------------- | --------------------------------------------------------------- |
| **Scanner**     | `String` → `List<Token>`        | Group characters into tokens; track line numbers.                |
| **Parser**      | `List<Token>` → `List<Stmt>`    | Recursive descent; build the tree; desugar `for` into `while`.   |
| **Resolver**    | `List<Stmt>` → scope-distance map | Static walk that binds every variable to a fixed scope depth.  |
| **Interpreter** | `List<Stmt>` → effects          | Visitor that walks the tree and evaluates it.                    |

The tree has two node families, `Expr` and `Stmt`, code-generated by
`tool/GenerateAst` into `Expr.java` and `Stmt.java`. Every pass that walks the
tree is a visitor over those types.

## Requirements

- A JDK — `javac` and `java` on your `PATH`
- `make`

## Build & run

```sh
make build                    # compile the interpreter
make run                      # start the REPL
make runfile FILE=test.lox    # run a script
make clean                    # delete compiled .class files
```

Under the hood:

```sh
javac src/com/craftinginterpreters/lox/*.java
java  -cp src com.craftinginterpreters.lox.Lox test.lox
```

**Exit codes:** `0` clean · `64` bad CLI usage · `65` scan / parse / resolve
error · `70` runtime error.

## The language

Dynamically typed, C-flavoured syntax, four value types (`number` — a 64-bit
double — plus `string`, `bool`, `nil`).

- **Expressions** — arithmetic with real precedence, `+` doubles as string
  concatenation, comparison and equality with no implicit coercion, `and` / `or`
  that short-circuit and return an operand.
- **Truthiness** — only `false` and `nil` are falsey; `0` and `""` are truthy.
- **Statements** — `print`, `var`, blocks with lexical scope and shadowing,
  `if` / `else`, `while`, and a `for` that is desugared away in the parser.
- **Functions** — first-class, closures capture their defining environment,
  arity checked at call time, `return` unwinds via a lightweight exception.
- **Resolver** — a static pass that fixes closure capture, makes variable
  lookup O(1) in scope depth, and rejects `var a = a;` and top-level `return`.
- **Native functions** — `clock()` returns seconds since the epoch.

`test.lox` exercises all of the above. Runtime errors report as
`message` followed by `[line N]`.


## Implementation notes

- **Recursive descent** — one method per grammar rule, each calling the
  next-tighter one, so precedence and associativity fall out of the call
  structure. Binary operators loop and nest left; `assignment` and `unary`
  recurse and nest right.
- **`for` is sugar** — the parser rewrites it as a `while` wrapped in a block,
  so the interpreter never sees a `for` node.
- **Error recovery** — on a parse error the parser throws, is caught at the
  declaration boundary, and `synchronize()` skips to the next statement so one
  broken line doesn't cascade.
- **Closures** — a `LoxFunction` holds the environment it was declared in.
  Calling it creates a fresh environment chained to that closure, binds the
  parameters, and runs the body.
- **`return`** — thrown as a `Return` exception that carries the value and
  unwinds to the call site.

## Status

Implemented and tested through the resolver (Chapters 4–11 of the book):
scanning, the full expression grammar, statements, variables and scope, control
flow, functions, closures, and static resolution.

**In progress** — classes, methods, `this`, inheritance and `super`. The
keywords are already reserved by the scanner; the semantics are being shaken
out.
